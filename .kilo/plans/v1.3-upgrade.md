# Crumb v1.3 Upgrade Plan

## Goal
Make `crumb` a genuinely useful daily-driver CLI scratchpad by closing real gaps
(bugs, missing documented features, polish) WITHOUT adding complexity.

## Constraints (from project memory)
- Go, Cobra, stdlib only (no new deps).
- Black-box tests live in `tests/` package (`go test ./...`).
- Commands: add file in `cmd/`, register via `init()` + `RootCmd.AddCommand`.
- Mutations go through `store.Update(func(*store.CrumbData) error)`.
- Primary branch is `master`; feature branch `feat/upgrade-crumb-v1.3`.

## Phase 1 — Analysis (sub-agent audit)
Independent audit: README vs implementation, bugs, test gaps, proposed features.

## Phase 2 — Implementation (sub-agent)
Ship the agreed simple, high-value features + tests + README/CHANGELOG sync:
- `fail` command (documented in README but missing) — completes done/cancel/fail trio.
- `version` command / `--version` flag (cobra Version field) — polish.
- `edit <id> <text>` — reword a task (append-only stays for notes/ideas).
- README/CHANGELOG accuracy: document delete, clear, fail, version, edit.
- Collision-safe task IDs (tiny hardening).
- Tests for fail, edit, version, ID uniqueness.

## Phase 3 — Verify
- `go build ./...`
- `go vet ./...`
- `go test ./...`
